Technical Privacy Policy, Permission Manifest & Security Architecture Specification

This specification represents the formal privacy documentation, data protection impact assessment, and runtime security model for the Android software application known as Dynamic Edge Gesture Control. It provides an exhaustive, unambiguous disclosure of every single permission, background thread, hardware hook, memory lifecycle, and third-party data transit pathway utilized across the entire lifecycle of the application.

Section 01

Foundational Architecture & The Local-First Processing Model

In an era dominated by cloud-tethered software paradigms where user telemetry, configuration state, and contextual hardware interactions are routinely harvested, synchronized, aggregated, and monetized within centralized relational databases, Dynamic Edge Gesture Control explicitly repudiates this computational philosophy. The entirety of this software system is engineered from the ground up to adhere to the rigorous principles of the Strict Local-First Computation Protocol.

Every computational heuristic, touch boundary calculation, coordinate projection matrix, gesture recognition classifier, notch bounding-box interceptor, radial pie menu layout generator, and encrypted local note storage engine operates entirely within the volatile Random Access Memory (RAM) and isolated application sandbox directory allocated strictly to our Linux User Identifier (UID) by the Android operating system. At no juncture in the software's execution lifecycle are your gesture habits, shortcut selections, personal configuration files, screen coordinate histories, or private notes serialized into external packets for transmission to any proprietary, private, or developer-operated remote server.

Core Technical Guarantees of the Zero-Telemetry Kernel

  • Absence of Developer Remote Infrastructure: The developer does not deploy, operate, manage, rent, lease, or route traffic through any proprietary backend servers, virtual private servers (VPS), AWS/GCP cloud clusters, or PostgreSQL/MySQL/MongoDB databases for user record retention.
  • Zero Authentication Barriers: The software contains no user account registry, email registration module, OAuth login flow, phone number validation handshake, or persistent user profiling identifier. You launch the app and consume utility instantly without surrendering digital identity markers.
  • Volatile State Transience: Raw screen coordinates ($x, y$ cartesian pixel values) generated during edge swipes, notch taps, and touch interactions are evaluated strictly in volatile RAM, translated into an internal action intent (e.g., GLOBAL_ACTION_BACK), and immediately dropped from memory without leaving forensic traces on flash storage.
  • Strict Cryptographic Offline Enclave: The optional "Quick Notes" and "Media Vault" features store records purely within the application's internal sandboxed directory (/data/user/0/com.m.payra.gesture.control.app/) guarded by the Android Linux kernel's multi-user discretionary access control (DAC).
Section 02

Statutory Lexicon & Architectural Terminology

To maintain total precision and preclude ambiguities during legal review, regulatory audit, or technical source-code verification, the following terms are defined in accordance with internationally recognized standards:

AccessibilityNodeInfo & AccessibilityEvent

The official Android framework classes representing the hierarchical view tree and interactive UI state transitions of an active application. While the operating system transmits these objects to enabled accessibility services, Dynamic Edge Gesture Control specifically ignores the text payload, content descriptions, input text buffers, and password values contained within these structures.

Sandboxed Internal Storage

A dedicated, hardware-encrypted directory on the device's physical non-volatile flash storage assigned exclusively to our app by the Linux kernel security manager. No other third-party application installed on the operating system possesses read, write, or traversal permissions over this directory without explicit root access.

Foreground Service Execution

A specialized Android system execution state marked by a permanent, non-dismissible notification that grants the application persistent operational privileges in RAM, thereby immunizing its edge touch detection hooks from aggressive operating system low-memory-killer (LMK) eviction algorithms.

Pseudonymous Telemetry

Machine-generated diagnostics, including stack traces, device hardware vendor strings, OS API levels, and resettable Google Advertising Identifiers (GAID), which facilitate statistical aggregation and troubleshooting without associating records with a verifiable human name, physical address, or national ID number.

Section 04

The Android Accessibility Service (BIND_ACCESSIBILITY_SERVICE) Protocol

Prominent Legal Disclosure Under Google Play Policy

Dynamic Edge Gesture Control requires the declaration and activation of an Android Accessibility Service. In compliance with the Google Play Accessibility API Policy, users are hereby explicitly, prominently, and unequivocally informed regarding the exact operational constraints and technical boundaries of this service.

1. Why Accessibility Is Technically Required

In the Android security sandbox architecture, standard user-space applications are strictly barred from performing system-level navigation injections (such as triggering an operating-system-wide Back navigation, transitioning to the Home Screen, displaying the Recent Apps task switcher, pulling down the Notification Shade, opening Quick Settings, triggering Split Screen, or commanding the device to display the Power Menu) without holding elevated system privileges or root access.

The Android Accessibility API provides the official, secure framework (performGlobalAction()) enabling our software to execute these precise system primitives reliably across all supported Android versions without tampering with operating system firmware.

2. Technical Confinement & Content Rejection Safeguards

While the underlying Android Accessibility Service pipeline possesses the technical capacity to deliver serialized window content to connected services, Dynamic Edge Gesture Control enforces hardcoded structural isolation within its service implementation:

  • Zero Text Node Inspection: Our service entirely suppresses the inspection of AccessibilityNodeInfo.getText(), getContentDescription(), or child view hierarchies. It cannot read text typed into chat applications, emails, banking interfaces, search bars, or web browsers.
  • Absolute Keylogging Protection: The application does not declare the flag to monitor hardware or soft keypress events (FLAG_REQUEST_FILTER_KEY_EVENTS is excluded from the accessibility configuration XML). It is physically and programmatically impossible for the service to record keystrokes, passwords, two-factor pins, or credentials.
  • Touch Boundary Confinement: Touch intercepts are restricted exclusively to ultra-thin edge zones (e.g., 8–24 pixels along screen margins) and the designated camera cutout perimeter. Once a swipe moves into the primary viewport area, coordinate consumption terminates, handing complete touch supremacy back to the foreground application.
Section 05

Window Management, Screen Overlays & Touch Injection

To construct responsive tactile edge triggers, dynamic camera notch status rings, and radial pie menus, the application relies on the system windowing manager through specific permissions:

android.permission.SYSTEM_ALERT_WINDOW WindowManager.LayoutParams

This permission allows the app to instantiate floating views utilizing the system window type TYPE_APPLICATION_OVERLAY. These views form the physical UI anchors of the edge handles and notch indicators.

• FLAG_NOT_FOCUSABLE: Ensures that touch focus is only seized within designated interaction zones, preventing the overlay from blocking keyboard inputs in underlying apps.
• Zero Screen Capture: The overlay contains no functionality to invoke the MediaProjection API. It cannot screenshot or record the visual contents of apps running beneath it.
android.permission.INTERNAL_SYSTEM_WINDOW (Not Declared) Secure Sandbox Verified

The application does not exploit private OEM signatures or unauthorized system window hooks. All overlay layers exist within standard user-space constraints established by Android 8.0 (API 26) through Android 15+.

Section 06

Foreground Execution Architecture & Power Optimization Exemptions

Modern Android operating system releases incorporate aggressive power management heuristics (such as Doze Mode, App Standby Buckets, and OEM task-killing daemons) engineered to throttle background execution. Because Dynamic Edge Gesture Control is a core utility that users expect to respond instantaneously (in under 10 milliseconds) to an edge swipe, the application declares specialized foreground service types:

FOREGROUND_SERVICE_SPECIAL_USE

Declared under Android 14+ requirements to sustain the gesture processing loop without background throttling. The user is perpetually informed of this active state via an ongoing system notification.

RECEIVE_BOOT_COMPLETED

Automatically registers a BroadcastReceiver when the operating system completes booting, re-initializing configured edge zones so users do not have to manually launch the app after a restart.

WAKE_LOCK

Prevents the system CPU from falling into deep sleep during active multi-step gesture sequences or rapid swipe-and-hold radial menu transformations.

REQUEST_IGNORE_BATTERY_OPTIMIZATIONS

Prompts the user to grant an exemption from battery optimization rules. This prevents aggressive OEM background killers from severing touch hooks during low battery conditions.

Section 07

Package Visibility Architecture (QUERY_ALL_PACKAGES Declaration)

android.permission.QUERY_ALL_PACKAGES Google Play Policy Compliant

Under Android 11 (API 30) and later versions, apps cannot query the list of installed applications by default. Dynamic Edge Gesture Control requests the high-risk permission QUERY_ALL_PACKAGES because its core functionality cannot operate without direct system package visibility:

1. Dynamic App Launch Docking

Allows users to search, filter, and assign any installed app or game directly to edge drawer slots, radial pie wedges, or notch tap shortcuts.

2. Contextual Gesture Exclusion

Monitors foreground package transitions to instantly suppress edge touch sensors when blacklisted apps (e.g., first-person shooters, digital drawing pads, or the camera viewfinder) are active.

Zero Network Transmission Pledge: Package inventories are queried on-demand directly via PackageManager.getInstalledApplications() in local volatile RAM. Lists of your installed apps are never compiled into telemetry payloads, shared with advertising SDKs, or synchronized externally.
Section 08

Hardware Peripherals, System Settings & Media Interception

The application provides deep integration with physical device hardware to serve as an all-in-one gesture control center. Each hardware permission is isolated to specific, user-configured actions:

CAMERA, FOREGROUND_SERVICE_CAMERA Flashlight & Quick Snapshot

Accessed via Android's CameraManager to toggle the hardware LED torch when assigned to a gesture (e.g., double-tapping the notch). The camera lens itself is only activated if the user explicitly triggers an on-demand snapshot shortcut. Captured images are saved straight to the device's local gallery or private vault without cloud backup.

RECORD_AUDIO, FOREGROUND_SERVICE_MICROPHONE Quick Voice Memo Shortcut

Enables users to map a hold gesture to quick audio recording. The microphone is never opened passively in the background. Recording begins strictly when the gesture is actively performed and stops immediately upon gesture release. Audio files stay in the app's sandboxed local storage directory.

WRITE_SETTINGS, MODIFY_AUDIO_SETTINGS, VIBRATE System Volume, Brightness & Haptics

WRITE_SETTINGS allows edge slider gestures to smoothly change system screen brightness without opening the Android Quick Settings panel. MODIFY_AUDIO_SETTINGS controls media and ringer streams directly. VIBRATE delivers precise tactile feedback through the device's linear resonant actuator (haptic motor) upon successful gesture recognition.

BLUETOOTH_CONNECT, BLUETOOTH_SCAN Accessory Quick Toggle

Under Android 12+ (API 31+), these permissions allow the app to display paired Bluetooth headphones and peripherals within the radial dock and reconnect to them on command with a single tap.

Section 09

Speed Dial & Contact Lookup Permissions

Dynamic Edge Gesture Control enables users to configure direct speed-dial shortcuts (for example, swiping diagonally from the upper right corner to immediately call an emergency contact or family member). This functionality is governed by two permissions:

CALL_PHONE

Executes an immediate Intent.ACTION_CALL without redirecting through the dialer pad when triggered by an assigned shortcut.

READ_CONTACTS

Used strictly when opening the contact picker inside the configuration settings to assign a phone number to a gesture. The app never uploads, aggregates, or syncs your address book.

Section 10

Geofencing & Situational Profile Automation

The application provides an optional contextual automation engine capable of altering gesture configurations based on your physical environment (e.g., enabling expanded media controls while in the car or disabling all notification shortcuts while at the workplace).

ACCESS_FINE_LOCATION & ACCESS_COARSE_LOCATION Local Geofence API Only

Rather than polling GPS coordinates continuously in the background (which drains battery life and introduces privacy risks), the app registers local hardware geofences via Google Play Services GeofencingClient. Location coordinates are stored strictly inside the device's local SQLite database and are never sent across any network connection.

Section 11

Biometric Authentication & Private Vault Encryption

For users who take advantage of the integrated Quick Notes and private media capture features, the application includes an authentication guardrail powered by USE_BIOMETRIC and USE_FINGERPRINT.

Biometric verification is handled entirely by the Android BiometricPrompt subsystem. The application never accesses raw fingerprint bitmaps, retinal scans, or facial geometry data. All authentication checks occur inside the hardware-backed Trusted Execution Environment (TEE) or Secure Element (SE).

Cryptographic keys guarding encrypted notes are derived using the Android Keystore system with AES-256-GCM encryption, guaranteeing that your data remains unreadable even if the physical device is inspected.

Section 12

Third-Party Software Development Kits (SDKs) & Advertising Telemetry

To ensure sustainable ongoing development while providing a free version of the app, network communication is strictly confined to official developer SDKs provided by Google LLC:

Google Mobile Ads (AdMob) Ad Network

AdMob serves banner, interstitial, and rewarded video ads. The SDK uses the Google Advertising ID (AD_ID) to serve personalized or non-personalized ads, perform frequency capping, and detect fraudulent clicks under Google's Advertising Policies.

Opt-Out Mechanism: You can reset or delete your Advertising ID at any time via Android Settings > Privacy > Ads.
Firebase Crashlytics Diagnostics

When a crash or unhandled exception occurs, Crashlytics captures diagnostic state information (device brand/model, OS build number, free RAM, and exception stack traces). These logs contain no personally identifiable user records and are used solely to debug app crashes.

Data Retention: Diagnostic crash reports are retained on Google Cloud infrastructure for a rolling period of 90 days before automatic deletion.

In-App Purchases & License Verification Engine

The Pro upgrade for Dynamic Edge Gesture Control is processed entirely through the Google Play In-App Billing subsystem using the official Google Play Billing Library:

com.android.vending.BILLING & CHECK_LICENSE Zero Financial Footprint

The application never receives, processes, or stores credit card details, debit card credentials, bank account numbers, or billing addresses. Payment transactions are executed directly within Google Play's PCI-DSS-compliant security enclave.

Section 14

Data Lifecycle, Retention Schedules & Total Erasure Protocols

Because the application operates with a local-first storage design, data retention is managed directly by you on your physical device:

Configuration & Notes

Stored in private flash memory. Cleared immediately whenever you tap Clear Storage in Android Settings or uninstall the app.

Volatile RAM Buffers

Gesture coordinate metrics ($x, y$ coordinates) are held in RAM for a matter of milliseconds and cleared immediately upon gesture evaluation.

Crash Diagnostics

Anonymized crash telemetry logged via Firebase Crashlytics is automatically purged after 90 days in accordance with Google Cloud retention policies.

Section 16

Protection of Minors (COPPA & Age-Gate Standards)

Dynamic Edge Gesture Control is a general audience productivity utility designed for individuals who require advanced gesture controls on their Android devices. The application does not intentionally collect, solicit, or maintain personal information from children under the age of 13 (or under 16 within the European Union).

If a parent or guardian discovers that their child has configured the app and saved personal voice memos, photos, or notes, those assets can be removed instantly by clearing the app's local storage or uninstalling the software.
